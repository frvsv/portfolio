# Как добавить кейс-презентацию на сайт

Кейс — это обычная HTML-страница, собранная из **данных** (`data/cases/<slug>.js`) и **готовых блоков** (`js/case-blocks.js` + `css/case.css`). PDF на сайте не показывается и не публикуется: презентацию переносят в блоки один раз, дальше правят текст в одном файле.

```
data/projects.js            карточки на главной + шапка страницы проекта
data/cases/<slug>.js        содержимое кейса (тексты, картинки, порядок блоков)
js/case-blocks.js           блоки: данные → HTML
js/case.js                  загрузчик страницы кейса
css/case.css                стили блоков
projects/<slug>/index.html  страница-оболочка (одинаковая у всех проектов)
assets/projects/<slug>/     cover.webp · img/ · video/
../materials/<slug>/source/ исходные PDF (только для сверки) — ВНЕ папки сайта, не публикуются
```

## 1. Подключить новый проект (5 шагов)

1. **Картинки.** Обложка карточки → `assets/projects/<slug>/cover.webp` (16:9, ~3000×1691). Картинки презентации → `assets/projects/<slug>/img/*.webp`. Видео → `assets/projects/<slug>/video/`. Исходный PDF положите в `materials/<slug>/source/` (рядом с папкой сайта, не внутрь).
2. **Страница.** Папка `projects/<slug>/` уже есть для X-Mall и BarberBook. Для нового проекта скопируйте `projects/praybible/index.html` и поменяйте только `data-slug="<slug>"`.
3. **Данные проекта** — `data/projects.js`: у существующей заглушки поменяйте `status: "ready"`, `hasCase: true`, впишите `cover`, `coverW/coverH`, `coverBg`, `caption`, `category`, `platform`. Новый проект — новый объект в массиве `PROJECTS`. Порядок в массиве = порядок карточек на главной и ссылки «предыдущий / следующий».
4. **Контент** — создайте `data/cases/<slug>.js` по образцу `praybible.js` (`export default { cover, sections }`).
5. **Проверка** — см. раздел 6.

Менять `index.html`, роутинг и ссылки не нужно: карточка на главной ведёт на `projects/<slug>/`, страница сама подтягивает данные.

## 2. Формат данных

Правила текста в любых строках:

- `*слова*` — акцентный цвет (только в заголовках `title`);
- `\n` — намеренный перенос строки (редко: подписи выносок, узлы схем; в абзацах не нужен);
- пути к картинкам — **от корня сайта** (`assets/projects/<slug>/img/a.webp`), страница сама добавит `../../`.

```js
const IMG = "assets/projects/my-case/img/";
export default {
  cover: {                         // первый экран
    eyebrow: "Кейс · Веб-сервис",
    brand: { icon: {src, w, h}, wordmark: {src, w, h, alt} },
    tagline: "…",
    meta: [["Моя роль", "…"], ["Команда", "…"], ["Платформа", "…"], ["Срок", "…"]],
    result: "Результат: …",
    image: { src: IMG + "cover.webp", w: 1000, h: 1200, alt: "Описание картинки" },
  },
  sections: [                      // порядок в массиве = порядок на странице
    { id: "overview", n: "01", label: "Обзор", title: "Контекст *и задача*",
      lead: "Подзаголовок", leadNote: "Мелкая сноска под подзаголовком",
      blocks: [ /* блоки раздела */ ] },
  ],
};
```

`id` — уникальный, латиницей (якорь `#id`). `inlineHead: true` — шапку раздела рисует сам блок `feature` (см. ниже), как в разделах «Главный экран» и «ИИ-пастор».

## 3. Блоки

| `type` | Для чего | Ключевые поля |
|---|---|---|
| `cards` | карточки 2–4 в ряд | `cols`, `variant` (`persona` — с аватаром, `hypothesis` — выровненные чипы), `items: [{kicker, heading, avatar, parts, note}]` |
| `banner` | тёмный акцентный блок с картинкой | `kicker, title, text, image` |
| `method` | текст слева + кольцевая диаграмма справа | `left: {chip, text, note}`, `right: {chip, donut: {start, items: [{value, tone, pct, label}]}}` |
| `bar` | строка-вывод с линией сверху | `text` |
| `note` | мелкая заметка | `text` |
| `compare` | таблица сравнения (на мобильном — карточки) | `head: [...]`, `rows: [[строка, ячейка, …]]` |
| `journey` | кривая эмоций + шаги | `title, points: [{label, emoji, level 0..1}], steps: [{label, text, tone}], note` |
| `insights` | строки «инсайт → откуда → решение» | `labels: {from, solution}`, `items: [{n, title, from, solution}]` |
| `palette` | палитра и шрифты | `main`, `aux` (`{hex, fg, desc, size}`), `fonts`, `sample` |
| `flow` | схема user flow | `start, auth, onboarding, home, menu, key, legend` |
| `feature` | текст + телефон (или видео) | `phone`, `phoneSide: "left"\|"right"`, `parts`, `subtitle`, `titleChip`, `head`, `align`, `note`, `video` |
| `timeline` | полосы этапов | `items: [{label, value, grow, tone}]` |
| `html` | **уникальный блок** | `html: "<div>…</div>"` |

`parts` — массив «частей» текста: `{chip: {text, tone}, text}`, `{paras: [...]}`, `{list: [...]}`, `{ordered: [...]}`, `{label, text}`. Тона чипов и плашек: `sun`, `mint`, `sky`, `ice`, `accent`.

### Телефон с выносками

`feature.phone = {src, w, h, alt, callouts}`; без `callouts` — просто картинка. Координаты выносок — в «единицах макета» (один прямоугольник `box: {w, h}`):

```js
callouts: {
  box: { w: 708, h: 645 }, phone: { x: 188, y: 0, w: 310 },
  chips: [{ text: "Пожертвования", side: "l", x: 157, y: 70, h: 38 }],   // side l: x — правый край, r: x — левый
  lines: [{ d: "M…", dot: [x, y], arrow: [x, y, "l"] }],                // линия от точки на экране к плашке
}
```

Снимите координаты с исходника (в Figma — размеры и позиции слоёв), подставьте — масштабирование автоматическое. На экранах уже 900 px выноски превращаются в обычный список под телефоном.

## 4. Видео

Слот уже есть в блоке `feature`:

```js
video: { src: "", poster: "", ratio: "328 / 667", label: "Видео демонстрации взаимодействий" }
```

Пока `src` пустой, показывается серый прямоугольник с иконкой (`role="img"` и подписью для скринридеров). Чтобы вставить видео: положите файл в `assets/projects/<slug>/video/demo.mp4` и впишите `src: "assets/projects/<slug>/video/demo.mp4"`, при желании `poster`. Разметку менять не нужно. Рекомендации: MP4 (H.264, AAC), до ~5 МБ, без автозвука; кнопки управления включены, автозапуска нет.

## 5. Главное правило: PDF — только первоисточник

Презентация нужна **один раз**, чтобы сверить содержание: тексты, числа, подписи, порядок и смысловые связи. Она не шаблон вёрстки и не часть рабочего процесса. Всё, что дальше правится, живёт в HTML-блоках, CSS-токенах и тексте `data/cases/<slug>.js`. PDF-просмотрщик не используется, исходные PDF лежат в `materials/` и не публикуются.

- **Содержание — слово в слово.** Не перефразируйте, не меняйте порядок и факты. Подтверждённые опечатки исправляйте сразу в данных; если слово может быть авторским названием, проверьте первоисточник, а не исправляйте наугад.
- **Вёрстку не копируют с слайда.** Диаграммы (user flow, пути) допускается переработать в стилистике сайта, сохранив все узлы, связи и подписи.
- **Картинки.** Макеты, телефоны, аватары — отдельные файлы (WebP). Целые слайды скриншотами не вставляем. Всегда `w`/`h` и осмысленный `alt` (декоративным — `alt: ""`).

## 6. Тексты, переносы и типографика

1. **Не переносите ручные переносы строк из PDF/Figma.** Пишите абзац одной строкой; строки формируются по ширине колонки (`text-wrap: balance/pretty`, `--measure`).
2. `\n` в строках данных — это *намеренный* разрыв (подпись выноски, строка диаграммы, подзаголовок узла flow). В обычных абзацах и заголовках `\n` не используется.
3. Висячие предлоги и союзы («в», «к», «с», «и», «о», «у», «а», «на», «по» и т. п.), тире и пара «число + слово» склеиваются автоматически функцией `typo()` в `js/case-blocks.js` — вручную `&nbsp;` ставить не нужно. Английские подписи узлов (`fnode`) обрабатываются без неё.
4. Не используйте `white-space: nowrap` на абзацах: допустимо только на коротких метках (бейдж гипотезы, имя гарнитуры).
5. Размеры, отступы и ширины берутся только из токенов `.case { --sp-*, --fs-*, --measure, --r, --gap, --block, --sec }` в начале `css/case.css`. Нужен другой размер — меняем токен или берём ступень шкалы, а не пишем число в правило компонента.
6. Метка гипотезы — один компонент (`hyp`, поле `hypothesis` у `feature` или `{hyp: "Гипотеза N"}` в `parts`). Она всегда стоит сразу под заголовком экрана и не переносится на другие экраны.
7. Одинаковые экраны продукта (`feature`) делают одним шаблоном: заголовок `--fs-h3`, колонка `--measure`, телефон `--phone`, между экранами `--feat`. Не подгоняйте отступы у отдельного экрана.

### Компоненты (соответствие блокам)

| Компонент | Где в коде |
|---|---|
| PersonaCard | `cards` + `variant: "persona"` |
| PersonaJourney / JourneyStep | `journey` |
| HypothesisBadge | `hypBadge()`, класс `.hyp` |
| UserFlowDiagram / FlowNode | `flow`, `fnode()` |
| TypographySpecimen | `specimen()` внутри `palette` |
| ProductScreenSection / FeatureDescription | `feature`, `featureText()` |
| MockupMedia | `mockup()`, `videoSlot()` |

## 7. Уникальные блоки и порядок

- **Порядок разделов и блоков** меняется перестановкой элементов в массивах `sections` и `blocks`.
- **Разовая вёрстка:** `{ type: "html", html: "<div class=\"my\">…</div>" }` — HTML вставляется как есть; стили добавьте в `css/case.css` с префиксом `.case .my-…`.
- **Повторяемый новый блок:** добавьте функцию `(данные, раздел) => "<html>"` в `REGISTRY` в `js/case-blocks.js` (или `registerBlock("тип", fn)`), стили — в `css/case.css`, строку — в таблицу блоков. Для текста используйте `plain()`/`rich()`, они экранируют HTML и применяют типографику.
- Будущие кейсы не обязаны повторять структуру PrayBible: берите только нужные блоки.

## 8. Как проверить перед публикацией

Локально: `python3 -m http.server 8765` в папке сайта → `http://localhost:8765/projects/<slug>/`. Для QA достаточно **одного** комплексного прохода.

**Контрольные ширины: 1440, 768, 390 и 360 px.** Каждая ширина проверяется один раз. Повторные скриншоты делаются только после исправления найденного дефекта и только для затронутого компонента и соседних секций.

1. **Визуально (секция за секцией):** нет висячих предлогов, обрезанного текста, наложений, лишних пустот; одинаковые компоненты выглядят одинаково; заголовки однотипных секций одного размера; метки гипотез у нужных блоков.
2. **Автоматически (в консоли браузера):** `document.documentElement.scrollWidth <= innerWidth` на каждой ширине; в Network нет 404; в Console нет ошибок (кроме недоступных внешних шрифтов в закрытой среде).
3. **Содержание:** сверьте с PDF (`pdftotext -layout файл.pdf` и текст страницы `document.querySelector(".case").innerText`). Расхождения допустимы только в тексте внутри скриншотов экранов приложения.
4. **Ссылки и пути:** меню, логотип, «предыдущий/следующий проект» работают; прямой переход по URL `projects/<slug>/` открывает кейс; нижней кнопки «На главную» нет.
5. **Публикация:** в загружаемой папке нет PDF презентаций и секретов; на GitHub Pages загружайте папку целиком (в корне — пустой `.nojekyll`); пути относительные, сайт работает и в подпапке репозитория.

## 9. Контрольный список перед выкладкой

- [ ] Тексты совпадают с PDF, подтверждённые опечатки исправлены
- [ ] Нет ручных переносов строк в абзацах и заголовках
- [ ] Порядок разделов и блоков как в презентации
- [ ] Все изображения с `w`/`h` и `alt`
- [ ] Видео-слот заполнен или оставлен заглушкой осознанно
- [ ] 1440 / 768 / 390 / 360 px: нет горизонтального скролла, всё читается
- [ ] Карточка на главной ведёт на страницу кейса
- [ ] Меню и «предыдущий/следующий проект» работают
- [ ] В публикуемой папке нет исходных PDF и секретов
