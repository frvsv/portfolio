# Как добавить кейс-презентацию на сайт

Кейс — это обычная HTML-страница, собранная из **данных** (`data/cases/<slug>.js`) и **готовых блоков** (`js/case-blocks.js` + `css/case.css`). PDF на сайте не показывается и не публикуется: презентацию переносят в блоки один раз, дальше правят текст в одном файле.

```
data/projects.js            карточки на главной + шапка страницы проекта
data/cases/<slug>.js        содержимое кейса (тексты, картинки, порядок блоков)
js/case-blocks.js           блоки: данные → HTML
js/case.js                  загрузчик страницы кейса
css/case.css                стили блоков
projects/<slug>/index.html  страница-оболочка (одинаковая у всех проектов)
assets/projects/<slug>/     cover.webp · img/ · video/
../materials/<slug>/source/ исходные PDF / Figma — ВНЕ папки сайта, не публикуются
```

## 1. Подключить новый проект (5 шагов)

1. **Картинки.** Обложка карточки → `assets/projects/<slug>/cover.webp` (16:9, ~3000×1691). Картинки презентации → `assets/projects/<slug>/img/*.webp`. Видео → `assets/projects/<slug>/video/`. Исходный PDF положите в `materials/<slug>/source/` (рядом с папкой сайта, не внутрь).
2. **Страница.** Папка `projects/<slug>/` уже есть для X-Mall и BarberBook. Для нового проекта скопируйте `projects/praybible/index.html` и поменяйте только `data-slug="<slug>"`.
3. **Данные проекта** — `data/projects.js`: у существующей заглушки поменяйте `status: "ready"`, `hasCase: true`, впишите `cover`, `coverW/coverH`, `coverBg`, `caption`, `category`, `platform`, `figma` (необязательно). Новый проект — новый объект в массиве `PROJECTS`. Порядок в массиве = порядок карточек на главной и ссылки «предыдущий / следующий».
4. **Контент** — создайте `data/cases/<slug>.js` по образцу `praybible.js` (`export default { cover, sections }`).
5. **Проверка** — см. раздел 6.

Менять `index.html`, роутинг и ссылки не нужно: карточка на главной ведёт на `projects/<slug>/`, страница сама подтягивает данные.

## 2. Формат данных

Правила текста в любых строках:

- `*слова*` — акцентный цвет (только в заголовках `title`);
- `\n` — перенос строки;
- пути к картинкам — **от корня сайта** (`assets/projects/<slug>/img/a.webp`), страница сама добавит `../../`.

```js
const IMG = "assets/projects/my-case/img/";
export default {
  cover: {                         // первый экран
    eyebrow: "Кейс · Веб-сервис",
    brand: { icon: {src, w, h}, wordmark: {src, w, h, alt} },
    tagline: "…",
    meta: [["Моя роль", "…"], ["Команда", "…"], ["Платформа", "…"], ["Срок", "…"]],
    result: "Результат: …",
    image: { src: IMG + "cover.webp", w: 1000, h: 1200, alt: "Описание картинки" },
  },
  sections: [                      // порядок в массиве = порядок на странице
    { id: "overview", n: "01", label: "Обзор", title: "Контекст *и задача*",
      lead: "Подзаголовок", leadNote: "Мелкая сноска под подзаголовком",
      blocks: [ /* блоки раздела */ ] },
  ],
};
```

`id` — уникальный, латиницей (якорь `#id`). `inlineHead: true` — шапку раздела рисует сам блок `feature` (см. ниже), как в разделах «Главный экран» и «ИИ-пастор».

## 3. Блоки

| `type` | Для чего | Ключевые поля |
|---|---|---|
| `cards` | карточки 2–4 в ряд | `cols`, `variant` (`persona` — с аватаром, `hypothesis` — выровненные чипы), `items: [{kicker, heading, avatar, parts, note}]` |
| `banner` | тёмный акцентный блок с картинкой | `kicker, title, text, image` |
| `method` | текст слева + кольцевая диаграмма справа | `left: {chip, text, note}`, `right: {chip, donut: {start, items: [{value, tone, pct, label}]}}` |
| `bar` | строка-вывод с линией сверху | `text` |
| `note` | мелкая заметка | `text` |
| `compare` | таблица сравнения (на мобильном — карточки) | `head: [...]`, `rows: [[строка, ячейка, …]]` |
| `journey` | кривая эмоций + шаги | `title, points: [{label, emoji, level 0..1}], steps: [{label, text, tone}], note` |
| `insights` | строки «инсайт → откуда → решение» | `labels: {from, solution}`, `items: [{n, title, from, solution}]` |
| `palette` | палитра и шрифты | `main`, `aux` (`{hex, fg, desc, size}`), `fonts`, `sample` |
| `flow` | схема user flow | `start, auth, onboarding, home, menu, key, legend` |
| `feature` | текст + телефон (или видео) | `phone`, `phoneSide: "left"\|"right"`, `parts`, `subtitle`, `titleChip`, `head`, `align`, `note`, `video` |
| `timeline` | полосы этапов | `items: [{label, value, grow, tone}]` |
| `html` | **уникальный блок** | `html: "<div>…</div>"` |

`parts` — массив «частей» текста: `{chip: {text, tone}, text}`, `{paras: [...]}`, `{list: [...]}`, `{ordered: [...]}`, `{label, text}`. Тона чипов и плашек: `sun`, `mint`, `sky`, `ice`, `accent`.

### Телефон с выносками

`feature.phone = {src, w, h, alt, callouts}`; без `callouts` — просто картинка. Координаты выносок — в «единицах макета» (один прямоугольник `box: {w, h}`):

```js
callouts: {
  box: { w: 708, h: 645 }, phone: { x: 188, y: 0, w: 310 },
  chips: [{ text: "Пожертвования", side: "l", x: 157, y: 70, h: 38 }],   // side l: x — правый край, r: x — левый
  lines: [{ d: "M…", dot: [x, y], arrow: [x, y, "l"] }],                // линия от точки на экране к плашке
}
```

Снимите координаты с PDF/Figma (в Figma: размеры и позиции слоёв), подставьте — масштабирование автоматическое. На экранах уже 900 px выноски превращаются в обычный список под телефоном.

## 4. Видео

Слот уже есть в блоке `feature`:

```js
video: { src: "", poster: "", ratio: "328 / 667", label: "Видео демонстрации взаимодействий" }
```

Пока `src` пустой, показывается серый прямоугольник с иконкой (`role="img"` и подписью для скринридеров). Чтобы вставить видео: положите файл в `assets/projects/<slug>/video/demo.mp4` и впишите `src: "assets/projects/<slug>/video/demo.mp4"`, при желании `poster`. Разметку менять не нужно. Рекомендации: MP4 (H.264, AAC), до ~5 МБ, без автозвука; кнопки управления включены, автозапуска нет.

## 5. Правила переноса презентации

- **Тексты — слово в слово.** Не перефразируйте, не «улучшайте», не меняйте порядок блоков. Опечатки исходника переносятся как есть и перечисляются заказчику отдельным списком (в PrayBible: «ИИ-интерпритация», «контранстности», «Subscribtion», «Offer of a subscriptions»). Если фрагмент не читается — оставьте пометку в отчёте, не додумывайте.
- **Картинки.** Макеты, телефоны, аватары — отдельными файлами (WebP, ≤ 1000 px по длинной стороне для UI-картинок, 2× допускается для телефонов). Целые слайды скриншотами не вставляйте. Всегда задавайте `w`/`h` (резервирует место, нет скачков) и осмысленный `alt`; декоративным — `alt: ""`.
- **Подписи.** Хранятся в данных рядом с картинкой, а не «запечены» в картинку, если это не часть экрана приложения.
- **Ритм.** Расстояния между разделами и блоками задают переменные `--sec` и `--gap` в `css/case.css` — не подгоняйте отступы у отдельных блоков. Длинная строка заголовка — до 2–3 строк (работает `text-wrap: balance`).
- **Цвета.** Блоки используют токены сайта и четыре семантических оттенка в `.case` (`--tint-sun/mint/sky/ice`). Фирменные цвета продукта показываются только как содержимое (блок `palette`).

## 6. Уникальные блоки и порядок

- **Порядок разделов и блоков** меняется перестановкой элементов в массивах `sections` и `blocks`.
- **Разовая вёрстка:** блок `{ type: "html", html: "<div class=\"my\">…</div>" }` — HTML вставляется как есть (пишите только своё содержимое), стили добавьте в конец `css/case.css` с префиксом, например `.case .my-…`.
- **Повторяемый новый блок:** в `js/case-blocks.js` добавьте функцию `(данные, раздел) => "<html>"` в `REGISTRY` (или вызовите `registerBlock("тип", fn)`), стили — в `css/case.css`, описание — в таблицу выше. Не забудьте `esc()` для текста.

## 7. Как проверить перед публикацией

Локально: `python3 -m http.server 8765` в папке сайта → `http://localhost:8765/projects/<slug>/`.

1. **Сверка с PDF/Figma.** Откройте PDF рядом и пройдите раздел за разделом: заголовки, подписи, числа, порядок блоков, группировки. Для автоматической сверки: `pdftotext -layout файл.pdf` и сравните набор слов с текстом страницы (`document.querySelector(".case").innerText`). Расхождения допустимы только в тексте внутри скриншотов экранов приложения (он не извлекается из HTML).
2. **Ширины:** 360, 375, 390, 430, 768, 1024, 1440, 1920 — нет горизонтальной прокрутки (`document.documentElement.scrollWidth <= innerWidth`), заголовки не рвутся некрасиво, таблица и выноски перестроились.
3. **Ссылки и пути:** все картинки загружаются (вкладка Network без 404), верхнее меню, логотип, «предыдущий/следующий проект», кнопка Figma работают; нижней кнопки «На главную» нет.
4. **Доступность:** у каждой картинки есть `alt`, заголовки идут по порядку (`h1` → `h2`), фокус виден при Tab, при `prefers-reduced-motion` ничего не мигает.
5. **Публикация:** в загружаемой папке нет PDF презентаций (они лежат в `materials/`), нет секретов и токенов; при размещении на GitHub Pages положите пустой `.nojekyll` в корень (уже есть). Все пути в проекте относительные — сайт работает и в подпапке репозитория.

## 8. Контрольный список перед выкладкой

- [ ] Тексты совпадают с PDF/Figma, опечатки исходника перечислены
- [ ] Порядок разделов и блоков как в презентации
- [ ] Все изображения с `w`/`h` и `alt`, вес файлов разумный
- [ ] Видео-слот заполнен или оставлен заглушкой осознанно
- [ ] 360–430 px: нет горизонтального скролла, всё читается
- [ ] 768–1024 px и ≥1440 px: сетка не разваливается
- [ ] Карточка на главной: обложка, подпись, ссылка ведут на страницу кейса
- [ ] Меню, «предыдущий/следующий», Figma-ссылка работают
- [ ] В публикуемой папке нет исходных PDF и секретов
